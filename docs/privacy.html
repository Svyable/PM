Privacy & data practices · Prepared for v1 review

Local-first by design.

PM is a third-party Chrome extension, independent of OpenAI. This document describes what the PM code currently reads and stores, and the boundaries of that data. Updated November 18, 2026.

PM is a release candidate, not a verified Chrome Web Store product. This privacy description covers the locally installed extension's documented behavior; you should also review OpenAI's Terms of Use and your browser's privacy practices.

Information PM handles

  • Dispatch preferences: the prompt you type, selected conversation count, effort level, pacing, tab retention setting, and readiness timeout.
  • Project inventory: identifiers, chat URLs, titles, visible snippets, and update labels from ChatGPT Project pages that you choose to view or scan.
  • Run activity: selected chat IDs and URLs, message-send verification results, errors, approximate timing information, and queue state.
  • Observed browser activity: whether relevant ChatGPT tabs are open, whether responsive open tabs expose a generation indicator, and locally recorded visit timestamps.
  • Project OS management data: a Project-specific mission, definition of success, next action, user-authored tasks and milestones, priorities, due dates, notes, conversation labels and manual status; brief local run-history summaries.

PM checks for a newly rendered user message matching your chosen prompt to verify a send. In Project fleet mode, each new conversation receives an assignment specific to its role and the mission you provide; PM stores a local role-to-conversation mapping to support future continuation. It is not designed to retrieve, export, or store full assistant responses. PM does not ask for account passwords or read browser cookies.

Where information goes

PM uses Chrome local extension storage for preferences, the current/latest job, discovered project metadata, visit timestamps, Project OS boards, and recent run-history summaries. The extension has no PM-operated analytics server, database, third-party tracker, or remote code loader. There is no automatic sale or upload of this locally stored information to PM's maintainers.

When you explicitly launch a dispatch, the prompt is submitted to ChatGPT through the interface on the selected conversation pages, just as if you had typed and sent it. In new-thread mode, PM opens the Project's new-chat composer and submits that prompt as the first message of a freshly created conversation; it stores the resulting URL and ID locally when verified. ChatGPT processes that submission under its own policies. PM cannot control data handling by ChatGPT, Chrome, GitHub, or their underlying infrastructure.

Project Board exports and imports

Exporting a Project Board creates a JSON file in your browser containing the Project ID plus any goals, task descriptions, deadlines and notes you entered. This backup may contain sensitive text; you control where it is stored or shared. Importing requires a user-selected JSON file for the same Project ID and an explicit replacement confirmation. Importing changes PM's own local Board data, not ChatGPT conversations, messages or Project configuration. Up to 500 tasks and 1,000 tracked conversation IDs are supported per board. PM does not automatically upload these files.

PM's Project workstream status (Working, Waiting, Blocked, Done), task completion and deadlines are user-authored annotations. They do not imply PM read a chat's response, verified an AI job completed, or accessed a private ChatGPT status API.

Permissions and purpose

  • chatgpt.com host access: read visible Project conversation links and interact with the chat composer only when a dispatch is triggered.
  • tabs: open the selected conversations, identify project tabs, and display open-tab status.
  • storage: persist preferences, inventory, visits, task boards, workstream notes, run history and job recovery state locally.
  • scripting: reconnect the UI adapter if a ChatGPT tab predates extension installation or update.
  • alarms: check and recover from interrupted or delayed dispatch states.

Retention and control

PM does not currently apply automatic time-based deletion. Project metadata and visit records can persist in the browser profile while PM remains installed. Saved Project fleet mappings and missions also persist locally until removal; no PM-operated external fleet server is used. Exporting a run log saves a separate JSON file on your device that may contain the prompt, chat URLs, and errors; share it only if you choose to.

To discontinue data collection, disable PM at chrome://extensions. To discard extension-local data, uninstall PM through Chrome's extension management controls. Previously exported files should be deleted separately. A dedicated selective-clear control is on the v1 roadmap and is not claimed to exist yet.

What PM cannot accurately report

The visible ChatGPT Project interface does not provide a reliable universal read/unread flag. PM therefore reports visited rather than claiming messages were read. A detected “generating” count covers only responsive open tabs inspected by PM; it is not an authoritative count of all jobs running in a project.

Contact, questions, and changes

For ordinary support and privacy questions, open an issue at github.com/Svyable/PM/issues. Do not put private prompts, account information, or sensitive conversation contents into public issues. If the extension's data practices change, this page and the extension's release notes should be revised before deployment.
