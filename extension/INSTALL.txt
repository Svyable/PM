PM 0.13.0 — Proceed Methodically (v1 feature candidate)

Install:
1. Extract the ZIP.
2. Open chrome://extensions and enable Developer mode.
3. Choose Load unpacked, then select the extracted extension/ folder.
4. Reload an already-open ChatGPT Project overview page.

Choose what PM does:
- Continue existing: send your instruction to existing threads in the Project.
- Start new: submit your instruction as the FIRST message in brand-new conversations inside the Project.
- Mixed: select how many NEW threads to create; the rest continue existing chats.
  PM continues existing chats first and then creates new threads.

Start with a test run of ONE conversation (High effort or Keep current).
Review the actual message and project membership before scaling.
New chats are created by sending a message; PM does not create blank threads.
Unconfirmed sends are NEVER retried automatically.

Independent candidate, not affiliated with OpenAI. Usage limits and service rules apply.
Source and support: https://github.com/Svyable/PM

Effort-picker fix: PM now detects an already-selected High effort and waits for slow picker menus. If effort remains unverified, it will not Send. You can choose Keep current to test the rest of the workflow, but that does not set High for you.

Full Command Center:
- The PM toolbar icon opens Chrome's native resizable side panel. No popup.
- A small PM launcher on Project overview pages opens the same panel.
- Reconnect is automatic. Keep a Project overview open; select the intended Project before Launch.
- Stop any active old-version run before updating the extension.
- If ChatGPT redirects before Send, PM will try restoring the original queue tab without double-sending.

The Project launcher opens the window-wide Chrome side panel; switch tabs freely while monitoring PM.

For v0.13.0 the Project launcher opens the Chrome side panel across the whole browser window, so the panel stays available when you switch tabs.

Project fleets (0.11): Choose Seed a project fleet, select Business/Science/Math/Brainswarm, enter one mission, review the roles, and Launch. Then choose Continue a saved project fleet to dispatch personalized prompts to the same mapped chats. PM seeds an existing ChatGPT Project; it does not create the Project container itself. Start with 1–2 test roles in a disposable Project.

Submit reliability: real editor input is required; no direct contenteditable text rewrite. PM resolves a live Send button and attempts submission only once. If no Send control is found, it tries Enter once, then verifies a new matching user message. Never blindly retry an uncertain submission.

Version 0.13.0: Prefer the enabled Send in the active composer. If ChatGPT exposes no Send control, PM tries one native form submission (if supported), otherwise one Enter event. Never manually repeat an uncertain send without inspecting the conversation.

PM 0.12 PRIME-TIME ACCEPTANCE:
- The side panel automatically checks a live Project composer (no manual Reconnect).
- A new matching user turn can be verified after ChatGPT navigates without resending.
- Usage/rate-limit notices pause dispatch; never try to bypass account limits.
- After navigation with an unsent PM draft, inspect/clear the draft before Resume.
- If local fleet-role storage fails, PM pauses instead of repeating a verified prompt.
- Try one harmless prompt in a disposable Project before dispatching a larger fleet.
- Successful automated CI is not proof of a live signed-in Chrome submission.
